# Security Policy

## Supported Versions

Security fixes are applied to the latest released version of `jiosaavn-dl`. Older versions and older Git revisions are not maintained with security backports.

| Version | Supported |
| --- | --- |
| Latest release | Yes |
| Older versions and revisions | No |

## Reporting a Vulnerability

Do not report vulnerabilities through public GitHub issues, pull requests, or discussions.

Use one of these private channels:

1. **GitHub Private Vulnerability Reporting:** Open the repository's **Security** tab and select **Report a vulnerability**.
2. **Email:** Send the details to `kenipratik9@gmail.com`.

If GitHub private reporting is unavailable, use email and do not include passwords, access tokens, cookies, or other credentials in the report.

## What to Include

Please include as much of the following as possible:

- A description of the vulnerability and its security impact.
- Affected versions, commits, or installation methods.
- Steps to reproduce the issue, including a minimal URL, input file, configuration, or command line where applicable.
- Relevant logs or error messages with secrets and personal data removed.
- Any known workaround or mitigation.
- Your name or preferred credit, if you want to be acknowledged.

## Response Process

- The maintainer will acknowledge receipt within a reasonable time, normally within seven days.
- The maintainer will investigate and validate the report.
- If accepted, a fix will be prepared and released as soon as practical.
- Affected users will be told which versions are fixed and how to upgrade.
- Public disclosure will be coordinated with the reporter, except where disclosure is required by law.

Please do not demand a public disclosure timeline that could expose users before a fix is available.
